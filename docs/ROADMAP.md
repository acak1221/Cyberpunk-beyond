# План развития

Этот документ описывает, что уже сделано, что идёт следующим и в каком порядке. Каждый пакет выходит отдельным запросом на слияние в `main` и сразу публикуется на GitHub Pages.

## Принципы

- **Без сервера и без учётных записей.** Данные живут в браузере игрока. Онлайн-комнаты работают через общедоступные MQTT-брокеры, сообщения шифруются и подписываются на устройстве.
- **Книга остаётся у владельца.** В приложении нет текста книги: только цифры правил, собственные формулировки и номера страниц. PDF игрок подключает сам.
- **Правила сверяются с книгой.** Каждая механика несёт ссылку на страницу, расхождения записаны в `docs/corebook-audit.md`.
- **Данные игрока важнее всего.** Любое изменение хранения проходит проверку на обновлении со старой версии, а замена или удаление всегда обратимы.
- **Каждое изменение с тестом.** `npm test` обязан проходить, новые ошибки сначала воспроизводятся тестом.
- **Русский текст — на «вы»**, без канцелярита, одинаковые термины во всех разделах.

## Что уже есть

- Листы персонажей, три способа создания, развитие за ОУ, киберимпланты и Человечность, портрет.
- Броски с модификаторами, бой (дальний, ближний, автоогонь, зоны, укрытия), критические травмы, лечение и ремонт.
- Трекер инициативы и кампании, журнал, библиотека НИП, часы, таблицы, погода.
- Сеть: архитектуры, программы, действия нетраннера.
- Каталог снаряжения, справочник правил, поиск по своей PDF-книге, закладки.
- Онлайн-комнаты без базы данных: броски, инициатива, часы, отправка листа Ведущему, ссылка и QR.
- Работа без сети (PWA), оформления «Обычное» (светлая и тёмная темы), «Досье» и «Киберпанк», русский и английский языки.
- **Пакет 1:** защита данных — карантин повреждённых записей, резервные копии, корзина на 30 дней и отмена; безопасный импорт (ограничение размера, вопрос перед заменой, прежняя версия сохраняется); устойчивые обновления без принудительной перезагрузки; исправления комнат и трекера.
- **Пакет 2 — удобство за столом:**
  - кнопки бросков показывают реальную прибавку; модификатор, LUCK и DV задаются у кнопок и действуют на следующий бросок;
  - быстрое изменение HP, компактные строки оружия с дистанцией (стр. 173), переход к автоогню, «режим игры», «не гасить экран»;
  - трекер для телефона: закреплённые «Назад» и «Следующий ход», свёрнутые заметки; книжные противники пачкой, встреча сразу в бой;
  - покупка и жизненный путь прямо с листа; шаг навыков в мастере со счётчиком, кнопками +/− и поиском;
  - книжные случайные таблицы (стр. 326, 331, 332), подготовка сохраняется на устройстве и пишется в журнал;
  - план сценария по схеме битов (стр. 395–407); навыки и атаки у своих НИП с бросками.
- **Пакет 3 — правила:**
  - общий слой эффектов: критические ранения (стр. 187–188), установленные импланты и уличные наркотики (стр. 227–229) сами учитываются в бросках, MOVE и инициативе; на листе виден список действующих эффектов;
  - трекер: инициатива персонажей как на листе, состояния ранения, Death Save и урон сквозь броню для противников, «выбыл», «отложить действие», «в начало очереди»;
  - репутация и «лицом к лицу» на листе (стр. 193–194), тест стиля игры (стр. 409);
  - улучшения семейной машины Кочевника из каталога по рангу Moto, варианты Upgrade Expertise у Техника (стр. 148).
- **Пакет 4 — комнаты:**
  - сообщения подписаны ключом устройства: выдать себя за другого участника нельзя;
  - ведущий привязан к ключу из ссылки на комнату; инициатива, счётчики и листы принимаются только от него;
  - защита от повторов и спама, участника можно скрыть, сообщения дополняются до одинаковых размеров, обрыв связи виден за секунды;
  - скрытые противники, сигнал «Ваш ход», бросок инициативы игрока попадает в трекер ведущего, в трекере видны текущие HP игрока, в комнате — репутация;
  - в README честно описано, что защищено, а что нет.
- **Пакет 5 — скорость, доступность, тесты:**
  - каталог не подвисает при вводе: поиск с короткой задержкой, по 48 карточек с кнопкой «Показать ещё», счётчик найденного;
  - бросок навыка обновляет лист на месте, без полной перерисовки (на медленном телефоне примерно вдвое–вчетверо быстрее);
  - общий сервис бросков `rolls.js`: броски из медицины, ремонта, хирургии, фармацевтики, терапии, опасностей, транспорта, NET, ближнего боя, автоогня, взрывов, критических ранений и ролевых способностей попадают в историю и в ленту комнаты;
  - доступность: кнопки бросков названы для скринридера, ссылка «К содержимому», фокус остаётся на месте после действия и переходит к заголовку нового экрана, мобильное меню удерживает фокус; контраст исправлен на всех экранах трёх оформлений;
  - оформление по умолчанию больше не обращается к Google за шрифтами (они нужны только виду «Киберпанк»);
  - браузерный набор проверок `npm run e2e` в CI: все экраны на двух языках, клавиатура, запуск без сети, комната через локальный брокер, правила доступности axe.
- **Оформление «Досье»:** лист в виде планшета персонажа — ряд характеристик, состояние и навыки отдельными колонками, панель с вкладками справа; на телефоне — вкладки по разделам. Светлая и тёмная темы, собственные рамки без сторонних ресурсов.

- **Магазин с корзиной:** плашка с деньгами покупателя, корзина, оплата одним действием.
- **Пакет 6 — десять возможностей:**
  - перенос архива файлом и с устройства на устройство по коду, напоминание о копии;
  - лист для печати и PDF, карточка для ведущего;
  - первый запуск: знакомство, персонаж-пример, пробный бой;
  - слой эффектов в инструментах медицины, ремонта, NET и терапии;
  - импланты в один тап и включаемые импланты со счётчиком раундов;
  - схема боя, связанная с трекером;
  - экспорт и импорт кампании, журнал для игроков в комнате;
  - свои предметы, импланты и противники;
  - комнаты: передача роли ведущего, помощник ведущего, файл ведущего;
  - «Досье»: панель подробностей броска и фильтры боя.

## Технический хвост

Эти пункты ничего не меняют для игрока, поэтому идут отдельно и небольшими шагами. Браузерный набор проверок из пакета 5 — страховка для них.

- **Реестр модулей и разделение `app.js`.** Сейчас три цепочки обработчиков перечисляют модули вручную. Первый шаг сделан (общий список модулей с областью правки); дальше — `App.register` и вынос экранов в отдельные файлы.
- **Ленивая загрузка экранов.** Отложена после замера: на замедленном вчетверо процессоре приложение запускается за ~1,2 с, из них разбор скриптов — ~0,3 с. Разбиение сэкономит не больше 0,15 с и усложнит работу без сети, поэтому вернёмся к нему, только если сборка заметно вырастет.
- **Шрифты вида «Киберпанк» со своего адреса** — чтобы и этот вид не зависел от Google.

## Дальше

Порядок здесь предварительный, он уточняется по отзывам с реальных игр.

1. **Экономика и простой.** Работа между сессиями, образ жизни и жильё, ежемесячные расходы, терапия.
2. **Синхронизация через собственное хранилище игрока** (по желанию), в дополнение к переносу по коду.
3. **Корзина:** раздельная оплата смешанной корзины из разных бюджетов, более низкая плашка на телефоне.
4. **Языки.** Вынос строк в отдельные файлы, чтобы добавить третий язык без правки кода.

## Что сознательно не делаем

- Учётные записи, собственный сервер и сбор данных.
- Текст и иллюстрации книги, готовые PDF.
- Материалы других книг линейки, пока владелец проекта не решит иначе: сейчас источник один — базовая книга правил.

## Как устроен выпуск

1. Задача берётся из пакета, ошибка сначала воспроизводится тестом.
2. `npm test` и сборка `node scripts/build.mjs`; браузерный набор `npm run e2e` (в CI запускается сам на каждом запросе на слияние).
3. Проверка в браузере: телефон и десктоп, все оформления и темы, оба языка; для хранения — обновление со старой версии.
4. Запрос на слияние в `main`, после слияния — проверка опубликованного сайта.
